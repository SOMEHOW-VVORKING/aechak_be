# MVP 초기 도메인 범위 (60-mvp-scope)

> 출처: 노션 「MVP 범위 축소 제안」 (SW 마에스트로/메모, 2026-07-08, v7.4 기준).
> SoT는 레포 `docs/prd/mvp-min/` — 범위 변경 시 원본 먼저 갱신 후 노션 → 이 문서 순으로 반영한다.
> 이 문서는 골격 세팅·패키지 구획의 기준이 되는 **요약본**이다. 기능/API/테이블 상세는 노션 서브페이지 참조.

## 1. 한눈에

- **규모**: 기능 **52** · API **90** · 테이블 **63** (8 BC)
  — v7.4: 적립금·로그인 3종·탈퇴·셀러 정산조회 추가, 채팅 제외
- **범위**: 구매자 코어 루프 + 셀러(경량) + 정산·리뷰·검색·찜·신고
- **제외 (도메인째 보류)**: 쿠폰 · SNS · 채팅 · 알림 · T&S 자동조치 — 5 BC / 39테이블.
  기능 오프 ≠ 테이블 드롭 — 스키마는 존치.
- **아키텍처**: 멀티모듈 모놀리식 + 이벤트 드리븐 (Kafka + Transactional Outbox)
- **일정 앵커**: W0 세팅 7/8~ → 중간점검 8/20 → MVP 완성 W11(9/22~28) → 최종점검 11/12~14

## 2. MVP 8 BC → 도메인 패키지 매핑

도메인은 모듈이 아닌 **패키지**로 구분한다 (00 §3-4). 아래가 `domain/`, `application/`, `boot/api/.../{도메인}/` 패키지 구획의 기준이다.

| BC | 테이블 | 패키지(안) | 주요 내용 |
| --- | --- | --- | --- |
| 회원 Member | 15 | `user` | 계정 원장(적립금 통합)·소셜 로그인 3종·펫·약관·배송지·탈퇴(익명화/법정보존)·유저 신고 |
| 셀러 Seller | 4 | `seller` | 입점 신청·서류·심사(어드민 UI 없음, DB/API 승인) |
| 상품·리뷰 Catalog & Review | 18 | `product` (리뷰 분리 여부는 구현 시 결정) | 카테고리(3단계)·옵션/재고·버전 스냅샷·찜·통계(평점)·리뷰·신고 |
| 주문·배송·클레임 Order & Fulfillment | 12 | `order` | 장바구니·주문그룹(TTL)·주문 상태머신(7종)·재고 예약·배송·클레임(취소) |
| 결제 Payment | 2 | `payment` | PG 결제·취소 — **헥사고날 L3 예외 적용** (10 §6) |
| 정산 Settlement | 4 | `settlement` | 정산 원장·지급(D+5 자동이체)·집행 배치·계좌 |
| 검색 Search | 2 | `search` | 최근 검색어·추천 검색어 (상품 검색은 DB 검색) |
| 운영·인프라 Ops/Platform | 6 | (도메인 아님) | `outbox_events`·`processed_events` = 이벤트 백본 핵심. 배너·공지·문의는 오프 |

## 4. 시스템·플럼빙 (batch / infra 대상)

- 공통 업로드
- 상태 자동전이 배치 4종: 주문서 TTL · 집화 D+1 · 배송완료 D+4 · 구매확정 5일
- 정산 집행 배치 · 개인정보 파기 배치
- **이벤트 백본**: Kafka + Transactional Outbox (`outbox_events` / 멱등 `processed_events`)
- 개인정보 암호화 (AES-256)

## 5. 골격에 반영된 것 / 안 된 것

- 반영: 모듈 지도(00 §1) 전체 + 초기 5개 도메인(user·seller·product·order·payment)의 domain/application 패키지 골격.
  user만 상세 템플릿(포트/어댑터·Command/Result·컨트롤러까지), 나머지는 구조와 에러코드 대역만.
- 미반영(후속): ERD 63테이블 반영, settlement·search 도메인 패키지, message 모듈(A-2),
  admin 실행 모듈(A-5: MVP 제외), Kafka·Outbox 실연동, 인증(소셜 로그인), 실 DB 전환.
